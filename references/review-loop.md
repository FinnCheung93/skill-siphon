# Review Loop

本文件定义用户要求独立审阅、subagent 审阅或 ReAct 式审阅循环时的执行方式。

## 1. 适用场景

使用本流程当用户要求：

- 用独立 subagent 审阅文档或修改结果。
- 反复审阅、修改、再审阅。
- 按 P0 / P1 / P2 / P3 收敛问题。
- 不是一次性“帮我看看”，而是要一个可结束的质量门。

如果用户明确要求 subagent，而当前环境没有可用 subagent，必须说明不可用，并改用用户确认的替代审阅方式；不要假装完成 subagent 审阅。

如果用户只要求“独立审阅视角”但没有指定 subagent，可先说明将使用分离的审阅 pass；高风险或写入权威文件时，再建议升级为真实 subagent。

## 2. 问题分级

| 等级 | 含义 | 是否阻塞完成 |
|---|---|---|
| P0 | 会导致目标失败、越权、严重误触发、静默修改、不可恢复损坏 | 阻塞 |
| P1 | 会明显削弱主要 workflow、造成重要遗漏、冲突或高概率误用 | 阻塞 |
| P2 | 有价值但不阻塞核心目标，主要影响清晰度、覆盖度或维护成本 | 不阻塞，可排期 |
| P3 | 风格、措辞、小幅优化或可选建议 | 不阻塞，可记录 |

默认完成目标：无 P0/P1；P2/P3 需要汇总，但不要求全部解决，除非用户明确要求。

## 3. ReAct 审阅循环

每轮按以下顺序：

1. **Reason**：说明本轮目标、已改文件、希望审阅者重点看什么。
2. **Act**：修改文件或整理候选。
3. **Review**：派独立 subagent 审阅，要求只输出 P0-P3 问题和总体结论。
4. **Triage**：主 agent 按优先级收拢问题：
   - P0/P1 必须处理或明确解释为什么误判。
   - P2/P3 可处理、记录或暂缓。
5. **Iterate**：如果仍有有效 P0/P1，继续下一轮。
6. **Stop**：当独立审阅结论为无 P0/P1，且主 agent 自检也通过时结束。

## 4. Subagent 审阅提示

给 subagent 的任务应具体、独立、可检查：

```text
请审阅以下目标和文件改动，不要修改文件。

目标：
<本轮目标>

请重点检查：
- 是否完整覆盖 source 的可迁移精华。
- 是否破坏 target skill 的边界和轻量结构。
- 是否存在重复、冲突、主文件变厚、reference 读取条件不清。
- 是否有静默修改、授权边界或完成条件问题。

输出格式：
P0:
- ...
P1:
- ...
P2:
- ...
P3:
- ...
总体结论：通过 / 不通过
阻塞完成的问题：列出 P0/P1；没有则写“无”。
```

## 5. 主 agent 收敛规则

- 不把 subagent 意见机械全收；先判断是否符合目标和 target 边界。
- 先处理 P0/P1，再看 P2/P3。
- 发现重复意见时合并处理。
- 如果 subagent 要求扩大 scope，默认降级为 P2/P3 或记录为后续建议。
- 每轮修改后必须重新验证结构或运行可用检查。

## 6. 完成汇报

最终汇报只保留：

- 改了哪些文件。
- 审阅循环跑了几轮。
- P0/P1 是否清零。
- 剩余 P2/P3 如何处理。
- 验证结果。
